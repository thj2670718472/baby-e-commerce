# BabyCity 母婴商城

三端全栈母婴电商项目：Node.js 后端 API + Vue3 管理后台 + uni-app 移动端商城。

## 功能总览

- **移动端商城**：首页推荐、分类浏览、商品搜索、购物车、下单支付、订单管理（超时自动取消）、收货地址、商品收藏与评价、优惠券抽取与使用、积分签到/积分商城兑换、**限时秒杀**、育儿文章、人工客服（WebSocket）、AI 育儿助手（DeepSeek）
- **管理后台**：数据看板、商品管理、订单管理（发货/退货审核）、评价审核、积分商城管理、**秒杀管理（场次/秒杀商品/库存）**、育儿文章管理、客服聊天
- **后端**：JWT 认证、接口限流与登录锁定、CORS 白名单、事务化订单与库存扣减、优惠券/折扣计算、订单超时释放定时任务、秒杀原子扣库存（防超卖 + 每人限购 + 抢购频控）

## 目录结构

```
├── node11/      # 后端 API（Express + Sequelize + MySQL）
│   ├── routes/        # 路由模块（19 个）
│   ├── db/            # Sequelize 模型与数据访问层
│   ├── middleware/    # JWT 认证、限流
│   ├── utils/         # 配置、token、密码哈希、订单服务、定时任务
│   ├── ws/            # WebSocket 客服聊天
│   └── scripts/       # 建库/种子/测试脚本
├── vue11/       # 管理后台（Vue3 + Vite + Element Plus + Pinia）
└── uniapp11/    # 移动端商城（uni-app，可编译到小程序/App/H5）
```

## 环境要求

- Node.js 20+
- MySQL 5.7+ / 8.0
- 微信开发者工具（如需运行小程序端，配合 HBuilderX 使用）

## 快速开始

### 1. 后端（node11）

```bash
cd node11
npm install
cp .env.example .env       # 按需修改数据库密码等配置
npm run init-db            # 建库 + 建表 + 演示数据 + 管理员账号，可重复执行
npm start                  # 默认 http://localhost:3000，会同时打印局域网地址
```

`init-db` 做了四件事：创建数据库 `dbbabycity` → 同步 Sequelize 表结构 → 灌入演示数据（分类/商品/育儿文章/积分商城商品）→ 创建管理员账号。

### 2. 管理后台（vue11）

```bash
cd vue11
npm install
npm run dev                # http://localhost:5180
```

### 3. 移动端（uniapp11）

用 **HBuilderX** 打开 `uniapp11` 目录，运行到浏览器或微信开发者工具即可。接口地址规则：

- H5 开发：默认 `http://localhost:3000`
- 真机 / 小程序：在 `uniapp11/.env` 中设置 `VITE_API_BASE=http://<电脑局域网IP>:3000`（后端启动时会打印局域网地址），小程序开发者工具需勾选「不校验合法域名」

## 管理员初始化

项目不再内置固定管理员密码。首次执行 `npm run init-db` 时：

- 若配置了 `ADMIN_INITIAL_PASSWORD`（12-64 个字符），使用该密码创建管理员。
- 若未配置，则生成一次性随机密码，仅在初始化命令输出中显示一次。
- 管理员身份保存在 `tb_user.role` 字段中，不再根据用户名动态判断。
- 如果 `ADMIN_USERNAME` 已被普通账号占用，初始化会直接失败，不会把该账号自动提权。

登录后请立即修改管理员密码。

## 优惠券运营

管理员后台「优惠券管理」支持：

- 创建、编辑、启用/停用优惠券模板，配置面额、门槛、概率、总量、有效期和每人限领。
- 按用户批量发放优惠券，单次最多 200 人，并自动校验模板库存和每人限领。
- 查询发放与核销记录，按用户、手机号、模板和状态筛选。
- 作废未使用优惠券，记录作废人、时间和原因。
- 查看累计发放、未使用、已核销、过期、作废和优惠金额统计。
- 系统每小时自动把超过有效期的未使用券置为已过期。

`npm run init-db` 会创建两个可停用的演示模板，方便首次运行直接体验抽券流程。

## 积分商品

移动端积分商城商品卡片可点击进入详情页，展示完整介绍、所需积分、库存、已兑换数量、每人限兑、默认收货地址、配送说明和兑换规则。兑换时后端会强制校验上架状态、库存、积分余额、收货地址和每人限兑数量。

管理员后台「积分商城」支持维护商品详情、图片、积分、库存、排序、上下架、配送说明、兑换规则和每人限兑数量。

## 订单自动确认收货

订单发货后超过 `AUTO_CONFIRM_DAYS` 天（默认 7 天）仍未手动确认收货时，系统会每小时扫描一次并自动完成订单：

- 仅处理状态为「已发货」且有发货时间的订单
- 待付款、退货中、已取消等状态不会处理
- 与用户手动确认收货共用同一事务逻辑
- 自动累加销量并发放收货积分
- 重复扫描不会重复发放奖励

## 环境变量（node11/.env）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| PORT | 3000 | 服务端口 |
| DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD | - | MySQL 连接信息 |
| JWT_SECRET | - | token 签名密钥，务必改成随机值 |
| ORDER_TIMEOUT_MINUTES | 15 | 待付款订单超时自动取消时间 |
| AUTO_CONFIRM_DAYS | 7 | 已发货订单超过多少天未确认收货时自动完成 |
| ADMIN_USERNAME | admin | 首次初始化管理员时使用的用户名 |
| ADMIN_INITIAL_PASSWORD | 空 | 首次创建管理员密码，留空则随机生成并打印一次 |
| CORS_ORIGINS | localhost:5180 等 | 允许携带凭证的来源白名单，逗号分隔 |
| AI_API_KEY / AI_API_URL / AI_MODEL | - | DeepSeek 配置，不配则 AI 助手返回 503 |
| TRUST_PROXY | 空 | 反向代理层数；部署到 Nginx 后面时填写，否则限流拿不到真实 IP |
| RATE_LIMIT_MAX | 300 | 全局兜底限流：单 IP 每分钟请求数 |
| LOGIN_RATE_MAX | 20 | 登录接口单 IP 每 10 分钟尝试次数 |
| MAX_ORDER_ITEMS | 20 | 单笔订单最多商品行数 |
| ORDER_CREATE_MAX | 20 | 单用户每分钟下单次数 |
| UPLOAD_DAILY_LIMIT | 30 | 单用户每天上传图片张数 |
| UPLOAD_RETENTION_DAYS | 90 | 聊天图片保留天数，到期自动清理 |
| WS_MAX_PAYLOAD | 65536 | WebSocket 单帧字节上限，超限连接被关闭 |
| WS_MESSAGE_MAX | 20 | WebSocket 单连接 10 秒内最多消息条数 |
| WS_MAX_CONTENT | 2000 | WebSocket 单条消息最大字符数 |

## 自动化测试

`npm test` 使用 jest + supertest 对着独立的测试库 `dbbabycity_test` 跑（库名由 script 里的 `DB_NAME` 指定，**不会碰正式库**），覆盖：

- **订单核心链路**：下单扣库存、库存不足拒绝、支付状态流转、确认收货加销量积分、超时自动取消并回滚、退货审核回滚、并发下单不超卖
- **自动收货**：发货超过保底天数自动完成、重复扫描不重复奖励、近期订单和退货中/待付款订单不处理
- **交易一致性**：同券并发只核销一次、过期/停用券拒绝、积分抵扣 50% 上限、收货并发幂等、退货状态恢复、购物车结算清理、默认地址切换
- **认证权限**：无 token / 伪造 token 401、越权 403、登录接口、改密后旧 token 失效、同名注册不提权、WS 会话隔离、登录锁定按来源隔离
- **评价规则**：必须关联真实订单、不能重复评价、审核积分奖励幂等、并发审核只奖励一次
- **看板统计**：SQL 聚合销售额、小数金额累加、权限边界
- **秒杀**：场次时间边界、限购按件数累计且软删除不重置、抢购频控 429、下架商品拒绝、库存不足提示抢完、超时取消回补秒杀库存、20 人并发抢 5 件库存恰好成交 5 单、管理端价格/库存校验
- **优惠券运营**：模板创建/编辑、概率预算、批量发放、每人限领、记录查询、未使用券作废、统计汇总、过期任务和后台权限
- **积分商品**：图片与规则字段编辑、上架详情公开/下架管理员预览、兑换限兑校验、积分与库存扣减
- **安全加固**：伪装图片拒绝、上传日配额、停用账号无法登录且旧 token 失效、下架商品权限、订单状态机与库存回滚、下单行数上限、优惠券核销约束、WebSocket 消息长度与频率限制

测试文件在 `node11/test/`。跑单个文件：

```bash

                                   # 因为没带 DB_NAME 时会连到正式库
```

## 接口约定

- **统一响应**：`{ code, message, data }`，`code` 为业务码（200 成功）
- **认证**：登录后携带 `Authorization: Bearer <token>`（也支持 cookie `token`）；token 内含密码指纹，修改密码后旧 token 自动失效
- **分页**：列表接口（商品 `/goods`、订单 `/orders/list`、评价 `/reviews/goods/:id`）传 `page` + `pageSize` 时返回 `{ list, total, page, pageSize, totalPages }`，不传 `page` 时保持旧行为返回数组，兼容旧客户端
- **WebSocket 客服**：连接 `ws://localhost:3000`，首条消息需携带 `{ userId, role, token }` 完成身份校验
